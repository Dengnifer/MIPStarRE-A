## Audit Result

Issue #0007 has a coherent target design, but the current scripts are not ready for GitHub write-through operation. A shared adapter plus durable per-operation reconciliation state is required; adding isolated `gh` calls would leave ambiguous creates, post-merge push failures, and concurrent same-head publications unrecoverable.

### Data Model

Use flat optional frontmatter fields because the shell helpers operate on top-level scalars:

```yaml
github_repo: Dengnifer/MIPStarRE-A
github_number: 7
github_database_id: 123456789
github_url: https://github.com/Dengnifer/MIPStarRE-A/issues/7
github_sync: pending        # pending | synced | conflict
github_sync_reason: null
github_sync_updated_at: 2026-08-31T...
```

Local issue and PR numbers must never imply GitHub numbers: GitHub issues and PRs share one number namespace, while the local sequences are separate. Seed these fields from [github-migration-map.md](/home/drx/MIPStarRE-qpbt/results/telemetry/github-migration-map.md), rather than parsing that prose file during normal operation.

A record-level `github_sync` flag is only an aggregate. Add a durable, registry-owned operation journal, preferably one atomic sidecar per entity. Each operation needs a deterministic key, payload digest, prerequisites, state (`pending`, `applying`, `synced`, `superseded`, `conflict`), attempt count, remote object ID, timestamps, and classified last error. Keys should distinguish `issue.ensure`, `issue.parent`, `pr.head`, `pr.ensure`, `ci:<sha>:<context>`, `review:<sha>:<digest>`, and `merge.main:<merge-sha>`.

Define field ownership explicitly. Local records own workflow state, gate evidence, generated bodies, and desired labels; GitHub owns assigned identities and observed remote state. The brief does not define inbound synchronization for human edits made directly on GitHub. If those edits must update the offline registry, a separate explicit import policy is still needed.

### Idempotent Retry

Every command should commit the local mutation and pending operation before network access. Best-effort mode exits successfully with an actionable pending warning; required-online mode exits nonzero without rolling back local state.

Before creates, and after any ambiguous result, paginate the authoritative REST listing and match the stable local marker. Adopt one match, create on zero matches, and stop with `conflict` on multiple matches. Updates use GET, compare, PATCH, and verification. GitHub sub-issue attachment requires the child’s numeric database ID, not its issue number ([GitHub sub-issues API](https://docs.github.com/en/rest/issues/sub-issues)).

Classify failures: retry timeouts, connection failures, `429`, and `5xx` with bounded exponential backoff; retain missing CLI, unauthenticated CLI, validation failures, and other permanent `4xx` responses as loud pending/conflict states. After an ambiguous status or review POST, query the exact SHA/context or marker/digest before retrying.

Commit statuses are append-only and interpreted by SHA plus context, so identical latest states should be suppressed ([GitHub commit-status API](https://docs.github.com/en/rest/commits/statuses?apiVersion=2022-11-28)).

### Empty-Branch PRs

The current `pr_open.py` can create a local record with an unresolved or null head. Preserve that behavior, but detect `base..head` having zero commits and record `pr.ensure` as pending with reason `waiting_for_head`. Do not push and do not manufacture a placeholder commit.

After the first real commit, reconciliation pushes only the feature ref, translates local issue footers through stored mappings, and creates or adopts the marked GitHub PR. Re-running `pr_open.py` currently allocates another local PR, so active branch uniqueness or an explicit “reuse existing record” check is also required.

### Same-Head Publication

- CI: publish `MIPStarRE/local-ci` only for the manifest’s SHA after verifying the complete manifest, `partial: false`, matching local record and branch tip, and remote commit existence. A mapped PR head mismatch leaves publication pending; it must never cause publication on the newer SHA.
- Review: require successful exact-SHA CI, exact-SHA lane files, a final local branch check, and `remote head == commit_id`. Always use `event=COMMENT`; the body reports the local verdict and unresolved count. GitHub authors cannot approve their own PRs ([GitHub review documentation](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/about-pull-request-reviews?apiVersion=2022-11-28)).
- Identical marker/digest publications are no-ops. A materially changed review on the same SHA receives a new auditable COMMENT review.
- Current race gaps: `ci.sh` does not recheck the branch tip before final success, and `review.sh` finally rechecks only `pr.md`’s `head_sha`, not the actual branch tip.

### Merge and Push Ordering

1. Parse and validate the exact manifest and review files inside `run_gate`.
2. Persist a merge intent containing base tip and reviewed head.
3. Perform the local `git merge --no-ff`.
4. Atomically record `state: merged`, `merged_commit`, and a pending main-push operation.
5. Push only `refs/heads/main:refs/heads/main` with ordinary fast-forward protection.
6. Resolve ambiguous pushes by querying remote `main`; retry only when it remains safely behind, and mark divergence as conflict.
7. Verify GitHub reports the PR merged through commit ancestry. Do not close it through the issue endpoint. GitHub documents that a locally merged branch pushed to the default branch can mark the PR merged ([GitHub merge documentation](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/incorporating-changes-from-a-pull-request/about-pull-request-merges?source=post_page---------------------------)).
8. Only then synchronize issue closures and permit remote feature-branch deletion. Local cleanup may proceed once recovery metadata is durable.

### Contradictions and Defects

- [AGENTS.md](/home/drx/MIPStarRE-qpbt/AGENTS.md:16), [DESIGN.md](/home/drx/MIPStarRE-qpbt/local/DESIGN.md:3), and [issues-prs.md](/home/drx/MIPStarRE-qpbt/local/protocols/issues-prs.md:17) still declare a local-only replacement, contradicting [HANDOFF.md](/home/drx/MIPStarRE-qpbt/HANDOFF.md:29) and the [re-hybridization decision](/home/drx/MIPStarRE-qpbt/local/protocols/EVOLUTION.md:215).
- [main.md](/home/drx/MIPStarRE-qpbt/local/personas/main.md:39) calls GitHub native but still describes a post-cleanup “mirror” push instead of integrated merge recovery.
- The review agent’s prohibition on `gh` and pushes should remain, but the protocol must distinguish that sandbox boundary from publication performed afterward by the trusted wrapper.
- `issue_close.py` returns immediately for an already-closed local issue, preventing remote reconciliation. `pr_merge.py` similarly refuses merged records, so failed post-merge pushes require a separate reconciler.
- `pr_merge.py` checks that the CI manifest exists but does not parse its SHA, `partial`, or conclusion, contradicting `ci.md`’s claim that downstream gates read the manifest. Its `--allow-unreviewed` message claims the waiver is recorded, but no waiver is written.
- `github-sync.sh` is neither ref-bounded nor failure-classified: it uses `--all`, retries permanent failures, sleeps after the fifth failure, and never verifies the result.
- Generated local footers such as `Addresses #0006` would point to unrelated GitHub objects unless translated.
- `.github/` remaining frozen is not contradictory and must be preserved; GitHub-native records do not reactivate Actions.
