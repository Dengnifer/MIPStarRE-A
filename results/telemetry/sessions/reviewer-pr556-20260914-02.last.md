## Review
F1 violates the central per-key ceiling invariant. When `accounts.json` becomes invalid, names come from last-good cap files, but `account_homes()` fabricates defaults for the historical names. If either live entry used an edited `codex_home`, dispatches are attributed to one account while actually consuming another account’s key.

F2 follows from deriving the gate solely from the number of enabled entries. With only `second`, `third`, or a custom-home `primary` enabled, it writes `primary`; `owner-bin-codex` then refuses the required non-default `CODEX_HOME`. Derive the gate from actual enabled homes or replace the binary gate with an allow-list.

F3 is reproducible by lowering `ceiling` below `external_reserved`: `apply_fields()` raises but leaves the in-memory ceiling changed. Validate a copied entry and commit it only after all invariants pass.

F4 should record the comment after `apply_directives()` has successfully persisted the update and before posting the reply. The strict load at `accounts_file.py:549` also means the documented remote repair path cannot currently repair an invalid file.

F5 treats untrusted comment text as idempotency authority. Marker checks must verify the marker comment’s trusted author or use authenticated local state.

F6 writes `paused=false`, clears saved caps, and rewrites derived gates before invoking the installed controller. An invalid accounts file makes that controller fail strictly, despite the fallback-focused test passing only when no controller is installed.

F7 affects the normal cron invocation, which supplies no `--issue`. `progress_issue` is a run scalar and should use `strict_accounts=False`; occupancy and key census also need the documented last-good fallback.

F8 must treat an explicit syntactically valid `account` as authoritative: if it is no longer configured, drop the row rather than trying its endpoint. `ready_report.py:389` repeats the same fallback.

F9 permanently records inaccurate telemetry for keys added or edited after briefing. Label and endpoint resolution should read the same live source used for routing and home resolution.

F10 is observable with a stream containing both `401 Unauthorized` and `503 Service Unavailable`: it classifies as `auth` although the shipped policy lists `endpoint_5xx` first. Preserve policy order through loading and classification.

F11’s per-account probe lock covers only the external probe, not the surrounding health read-modify-write. Hold `controller.lock` across the whole manual operation to serialize it with ticks.

The exact-head local CI is reported green. The read-only review sandbox had no writable temporary directory, so temp-directory-based suites could not be independently rerun; pure checks reproduced F2, F3, F8, and F10.
