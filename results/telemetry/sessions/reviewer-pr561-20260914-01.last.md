## Review

**F1:** `owner-resume.sh` leaves the replayed manifest in `pause-state.json`. A later pause preserves it, and `merge_manifest` carries forward every previously signalled session but initializes from the fresh document, losing `replayed_at`. The next resume consequently plans those old sessions again. A reproduced merge retained the old `KILL` row and generated a new dispatch for it. A pause episode identifier or explicit reset after replay is required.

**F2:** `dispatch.sh` records `sandbox`, `job_class`, `effort`, `hardness_reason`, `persona`, `persona_ref`, and `prompt_file`, but `live_sessions` discards all of them. `session_command` later assumes they survived. This can trigger `account_router.py`’s “resume cannot switch model” check, restart a read-only role with `workspace-write`, or create a fresh session without its original task. The tests hide this by constructing resume manifests containing these fields manually.

**F3:** `{}` is a valid marker snapshot meaning no failures existed at T+0. Both `merge_manifest` and the CLI use truthiness, so that snapshot is discarded and retaken at landing time. Any marker created during the pause is then considered pre-existing and cannot be cleared.

**F4:** `land --phase last` records `failed_markers` before the subsequent anchored sweep. Killing a refresh lane can make its surviving merge-daemon wrapper write `pr<N>.failed` afterward. The sweep also omits `review.sh`, so killing only its nested dispatcher lets the wrapper publish failure or partial review evidence while resume schedules a fresh review.

**F5:** Mtime difference establishes chronology, not causality. The merge daemon remains active for the first 30 seconds, and detached work can fail naturally later. Those legitimate structured failure records are currently marked `created_by_landing` and unlinked.

**F6:** A new lane removes only `.done` and `.needs-attention`; old `.dispatch.log`, `.ci.log`, `.review.log`, and `.pr.md` files remain. A pause during a new warm, dispatch, merge, or build phase can therefore classify it as `review`, or even `done` when its old head still has green statuses.

**F7:** `lane.sh` explicitly resolves worktrees from Git’s registry before considering `.worktrees/<branch>`. The manifest instead invents that conventional path. For a registered worktree elsewhere, the recorded head becomes null and resume unnecessarily restarts from dispatch rather than using the recorded stage.

**F8:** `land()` sleeps `grace_s` after terminating classified sessions; the shell then unconditionally sleeps `GRACE_S` again. The default last-call-to-publish interval is only 30 seconds, and collapsed deadlines necessarily overrun.

**F9:** `local/protocols/meta.md` requires every protocol edit to ship with an evidence trigger and `local/protocols/EVOLUTION.md` amendment. Neither is present in this diff.

`git diff --check` and shell syntax checks passed. The supplied exact-head CI status is green; direct tempfile-based tests could not run in this read-only reviewer sandbox.
