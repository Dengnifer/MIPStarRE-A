## Review
F1: `canonical_lake_root` rejects only the raw string `/`, then canonicalizes at line 29. Values such as `/tmp/..`, `/./`, or a symlink to `/` therefore return `/`. Both repository-overlap guards subsequently miss because they compare `//`, and cleanup constructs `//$branch`. A valid branch named `home`, for example, can make line 112 remove `/home`. Canonicalize first, reject the canonical root, and add a non-destructive regression for aliases and symlinks to `/`.
F2: Slash-qualified branches are explicitly supported, but only the final target is tested with `-L`. If `<root>/codex` is a symlink elsewhere, the target for `codex/issue` is not itself a symlink and passes every check; `rm -rf` follows the intermediate component and removes the external directory. Validate the physical target and every ancestor beneath the canonical root immediately before preparation and deletion.
F3: `build-cache.md` requires consumers to refuse every path inside `hot-main/repo` or `hot-main/snapshots`. The existing check examines only `WORKTREE`; afterward the helper may place `.lake` anywhere. Configuring the Lake root beneath either protected tree therefore reintroduces a cache writer. Validate the resolved external target against those protected paths.
F4: `dispatch.sh` still passes only `-C <worktree> --sandbox workspace-write`. Codex limits writes to that workspace; additional writable directories require `--add-dir` or a writable-root setting ([sandbox documentation](https://learn.chatgpt.com/docs/sandboxing), [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)). Consequently agent builds and build-running hooks cannot write through the new symlink without escalation. Grant only the resolved branch target to writing sessions and cover the generated dispatcher argv.
