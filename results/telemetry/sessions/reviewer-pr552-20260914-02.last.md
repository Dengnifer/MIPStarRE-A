## Review

**F1:** Each successful fix phase creates a `[codex-auto-fix]` or `[codex-review-fix]` commit. The loop then calls `review.sh` without `--force-review`, while `review.sh:542-545` skips exactly those commits. Consequently no new-head marker exists, `loop_verdict` returns `NONE`, and every successful loop stops with exit 2. The bounded loop needs an explicitly permitted forced review and an end-to-end regression test.

**F2:** `lane.sh` logs `DRC` but never acts on a nonzero value. A branch with earlier checkpoint commits, or a worker that commits before failing, passes the clean-tree and commits-ahead checks and proceeds through merge, build, and publication. Nonzero dispatch must stop or park the lane before publication.

**F3:** `run_mode.py apply` writes `run-mode.json` before calling `capacity_controller.py init`. If policy validation or initialization fails, the new brief is canonical while old cap files, capacity state, model override, and account mode remain active. Stage the mode for controller initialization and publish atomically, or restore every previous output on failure.

**F4:** `capacity.md:114-118,183-185` explicitly permits `set 0` below the default floor and promises a full quiet window. `apply_aimd` immediately clamps the zero into `[floor, ceiling]`, producing cap 1 on the first healthy tick. The below-floor override needs persistent state or separate clamp handling.

**F5:** `fresh` can contain several unseen refusal rows, but only one decrease is performed before the cursor advances to `max(fresh)`. This violates `capacity.md:47-50`, which requires every further refusal in the window to multiply the cap. The second-resolution timestamp cursor can also discard a later row with the same timestamp. Process each unique row in order using a stable row identity.

**F6:** Crontab restoration failures at lines 173-175 do not set `RC`. Regardless, the script clears pause state, sends the resume message, and appends a successful `event=resume` before checking `RC` at line 308. Restoration and postconditions must gate the success announcement and telemetry; incomplete resumes need explicit failure evidence.

**F7:** `full-speed-mode.md:33-39` defines `accounts[].codex_home` for every account, and validation accepts a custom primary home. Dispatch unsets `CODEX_HOME` and restores it only for `second`; router resume affinity also hard-codes the primary home. This can probe one primary credential while sessions use another. Resolve the selected account’s home generically or reject unsupported primary values.

**F8-F11:** The lane must construct or validate `type(scope): subject` titles and the required `### Motivation`, `### Description`, and `### Testing` body. Active event-writing instructions must consistently use `telemetry.py event` and `events.d/`. The protocol enum must document `auth` and its nonretryable/death semantics. Finally, account mode is `both` whenever `second` is enabled, including a second-only brief; the current “more than one enabled” wording is obsolete.
