## Review

**F1-F2.** Both scripts bind evidence to `HEAD_SHA` but execute against the live worktree without requiring it to be clean. An uncommitted repair can make CI pass for code absent from GitHub; dirty contextual files can similarly hide findings from a reviewer. Refuse dirty worktrees before publication, or use an isolated checkout of the exact SHA.

**F3-F4.** CI marks only step contexts pending, while `review.sh` trusts the old `local-ci/summary=success`. Review rerequests are worse: `gh_common.post_review` keeps the old body, while `post_summary` merely warns on publication failure. An old approved body and green status can therefore survive a newly adverse review. Invalidate summaries with a fatal `pending` write before reruns, replace the published ledger, and make final status publication fatal.

**F5-F6.** After waiting for the fix lock, `autofix.sh` rechecks only the remote head. A superseded run can leave a newer local commit unpushed, after which the waiter operates on that commit using the old head’s statuses and count. Separately, reaching the cap between phases invokes terminal review before the accumulated commit reaches GitHub, then exits without pushing it. Recompute local/remote state and the cap under the lock, and route cap completion through push, CI, then exact-head review.

**F7.** The implementation defaults to `auto-fix-codex`, while `local/protocols/autofix.md` and the taxonomy specify `auto-fix-claude`. The cap ritual also never removes that label, so its supposedly once-only review can repeat. Use one documented label and remove it when the cap is reached.

**F8.** `/issues/N` also returns pull requests. Falling back after transport, authentication, or server failures can therefore classify a PR as an issue and select `main` for a write-enabled agent. Fall back only on a proven 404, and reject an issue response containing `pull_request`.

**F9.** The regex misses `Closes: #42` and qualified same-repository references, while the gate scans no commit messages. GitHub documents all of these as closing surfaces, so a parent with open sub-issues can still be closed on merge. Expand both the parser and scanned inputs, with regression tests. See [GitHub’s closing-keyword syntax](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue?apiVersion=2022-11-28).

**F10-F11.** `--adjudicated` checks only a prefix and current-head token; it does not establish four completed rounds or require checked, dispositioned findings and issue references. Gate 1 also accepts absent/null `draft`, contrary to `local/protocols/issues-prs.md:84-85`. Validate the complete adjudication record and require `draft is False`.

**F12.** `post_merge` refreshes `origin/main` and starts the warmer even if `fast_forward_base` refused divergent history. That can make future diff audits use the wrong base. Continue alias refresh, warming, and cleanup only after verified fast-forward, or bind the alias directly to the verified fetched GitHub base.

**F13-F14.** A change limited to `gh_common.py`, `wf_util.py`, `review.sh`, or `pr_merge.py` can produce eight skipped-success contexts without running `test_github_workflow.py`. Additionally, issue keys are optional, keyed adoption searches only 100 issues, and branch queries are not URL-encoded. Broaden workflow gating, require stable issue keys, paginate adoption, and encode query parameters.

**F15-F17.** The issue quick-start omits its required body argument, while the PR quick-start permits a footer-only body despite the mandatory three-section template. Scout instructions still alternately require editing/committing an issue file and returning a GitHub comment; moved briefs retain dead `issues/briefs/...` links. Finally, the hook’s per-commit count and “split the change” advice contradict the normative 400-line per-episode cap. Align these operator-facing contracts before merge.

No Lean or blueprint declarations changed, so source-statement fidelity and `sorry` review are not applicable. `git diff --check`, shell syntax checks, and Python AST parsing passed. The unit suite could not be rerun in this read-only sandbox because its temporary-directory setup had no writable location; the attached exact-head CI status reports success.
