## Review

Changes are required. This PR only changes workflow scripts, protocols, personas, and tests; no Lean declaration, blueprint theorem link, paper-gap note, `sorry`, or axiom was changed, so proof integrity and source-statement fidelity are not implicated.

**F1.** `autofix.sh:402-408` computes `LOCAL_TIP`, the merge base, and `FIX_ITERATIONS` before acquiring the branch lock at `:541-543`. Two runs can both observe four fixes; the first commits the fifth, fails to push, and releases the lock, while the queued second run re-reads the unchanged GitHub head and proceeds with the stale count, creating a sixth fix. With `pr_merge.py:25-28` no longer enforcing the count, the branch can exceed `FIX_CAP`. Recompute the local history after acquiring the lock and revalidate both heads, or retain an independent merge-time guard.

**F2.** `check_review` only requires `text.startswith("ADJUDICATION")` and the substring `head=<sha>` (`pr_merge.py:189-200`). A body containing only `ADJUDICATION` and that token passes, although `review.md:381-395` requires every remaining finding to be fixed or tracked, ticked, and given a disposition. Validate the round limit, exact head field, every finding/disposition, tracked issue references, and the authorized actor, or explicitly rewrite the protocol as a trusted free-form override.

**F3.** The cap check occurs only at the start of `run_phase` (`autofix.sh:695-697`), while the counter is incremented after the commit (`:773-774`). If the final selected phase changes the count from four to five and resolves all failures, the post-fix path runs CI and exits; the next invocation hits the “nothing to fix” return at `:536-538` before `cap_reached`. Since `review.sh` skips bot-prefixed heads, the final head has no review. Invoke the cap ritual immediately when the increment reaches the cap and add a regression test.

**F4.** The cap marker is keyed only by PR number (`autofix.sh:562`), and `gh_common.ensure_pr_comment` patches the existing PR-wide comment (`gh_common.py:205-239`), so a later head overwrites the earlier cap record. More importantly, `cap_reached` releases the fix lock before push and review (`autofix.sh:581-604`); another run can move the head, causing the forced review to skip or return without a verdict while the cap routine treats that as a warning. Use a head-bound marker, an explicit terminal state, a serialized handoff to review, and a verified review result. The cap event also needs the telemetry record promised by `autofix.md:182-184`.

**F5.** `meta.md:37-47` requires the incident in `results/telemetry/events.md` before the protocol edit and requires both to be committed together. The current `events.md` ends with the 2026-09-01 issue-0007 entry; it contains no PR #5 review-fix-cap incident, and the cited six-lane/adversarial audit is not present in this head. Add the evidence first or defer this amendment.

**F6.** The new fallback names `stages.jsonl` (`main.md:131-135`), but the committed file is `results/telemetry/stages.jsonl`. `main-session.sh:25-26` still refuses to start when `HANDOFF.md` is absent, and `HANDOFF.md` is absent here. Correct the path and make the launcher use the fallback, or remove the fallback claim and restore the required briefing artifact.

**F7.** The changed worker personas prescribe plain `fix(...)` subjects, while `AGENTS.md:689-690`, `issues-prs.md:37-38`, `DESIGN.md:109-110`, and the reviewer personas still describe all fixes as `[codex-auto-fix]`/`[codex-review-fix]`. `review.sh:429-435` skips those prefixes. Define the automation-versus-human distinction consistently in the authoritative documents and tests.

**F8.** The hook now runs the scope check before `MIPSTARRE_SKIP_HOOKS` (`.githooks/pre-commit:16-39`), but installer and contributor docs still describe that variable as a general one-off bypass. The hook also totals only the staged commit while `main.md:88-91` defines a per-episode budget, so multiple sub-400-line commits evade the stated limit. Either track cumulative episode state or document and test this as a per-commit heuristic.

**F9.** `main.md:107-110` directs escalation through a `needs-owner` issue, but that label is absent from `docs/CONTRIBUTING.md:285-356`; `gh_common.issue_create` rejects labels not returned by GitHub (`gh_common.py:313-328`). Provision and document the label, or use an existing taxonomy label and define the credential-blocked fallback.

**F10.** `review.md:262-269` changes an adverse review from requiring explicit user override to operator adjudication, while the same file says substantive criteria are unchanged (`:6-11`) and the pinned `docs/pr_review_management.md:11-13` says, “Never merge a PR without consulting the user.” The adjacent scope rules also still require owner approval after two workflow episodes. Record an explicit superseding owner decision and reconcile these documents, or retain the user-consent gate.

**F11.** The old merge check evaluated the fetched GitHub head at merge time; `autofix.sh` evaluates a local tip before locking. Sharing `MIPSTARRE_FIX_CAP` does not make those observations equivalent. The statement in `EVOLUTION.md:339-345` that the merge check “was never an independent bound” is therefore unsupported and should be corrected before using it as the safety rationale for retirement.

**F12.** `autofix.sh`’s trusted prompt pair still says “Commit and push” with `[claude-auto-fix]`/`[claude-review-fix]` and asks for GitHub MCP calls (`.github/prompts/auto-fix-*:42-57`). The wrapper appends a prohibition later (`autofix.sh:624-645`), but there is no hard enforcement. A model following the earlier trusted instruction could push an uncounted `[claude-*]` commit: the reviewer skips it and the retained counter counts only `[codex-*]`. Update both prompt pairs and add a guard test.

**F13.** The new test inherits `os.environ` and never sets `MIPSTARRE_FIX_CAP`; an ambient value of six or more would also let the old implementation pass. Pin the default in the test and add focused coverage for the autofix race and terminal-review path.
