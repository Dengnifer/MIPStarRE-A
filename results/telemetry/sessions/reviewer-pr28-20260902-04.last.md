## Review
F1 is a direct violation of `local/protocols/review.md:384-400`, which permits at most four full rounds. At round five, the script merely appends instructions, then unconditionally dispatches at `review.sh:978`. A clean fifth review can publish a successful status and merge without adjudication. Stop before model dispatch or reconcile a bounded terminal adjudication path with the exact-head merge gate.
For F2, `MIPSTARRE_SESSION_TIMEOUT=--help` makes GNU `timeout` print help and return zero without running Codex; this was reproduced directly. Telemetry can then record the empty capture as `status: done`. A value of `0` also disables the timeout. Validate a positive duration, terminate option parsing, and retain `--kill-after` in every execution path.
For F3, `run_agent` attaches the diff before `prior-ledger.md`. Under the new aggregate 100,000-byte cap, a sufficiently large diff leaves zero bytes for the ledger, although the task requires the reviewer to triage that attached history and forbids recovering it from caches. Reserve ledger capacity or attach the bounded ledger first.
F4 contradicts `local/protocols/review.md:90-102`, which specifies the trusted code-review prompt pair verbatim. The orchestrator persona authorizes GitHub queue management, issue creation, and sub-session dispatch, and has a conflicting output contract. Use a dedicated infrastructure-review persona/task while preserving reviewer restrictions.
For F5, cleanup always runs `sparse-checkout disable`, rather than restoring the previous configuration. Because `SPARSE_WORKTREE` is assigned before `sparse-checkout set`, even a failed setup can erase existing sparse state. The index mutation also occurs without dispatch’s per-worktree writer lock.
F6 and F7 violate `local/protocols/meta.md:35-47`. `sessions.md` still specifies a 20,000-byte per-file cap, a 256 KiB prompt ceiling, and direct repository capture; `review.md` still promises the previous prompt and model behavior. The evolution entry neither cites the triggering incident nor provides separate Trigger, Change, and Expected effect fields.
No Lean or blueprint files changed. `bash -n` and `git diff --check` pass. Existing PR-review tests pass but cover the legacy workflow YAML, not these new timeout, cap, history, prompt-routing, or sparse-state branches.
VERDICT: CHANGES_REQUESTED
