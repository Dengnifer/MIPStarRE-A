## Review

**F1:** The integration targets omit seven modules reachable from `MIPStarRE`, including the root itself and `MIPStarRE.LDT.Test.SurfaceVsPoint`. Combined changes can therefore break untouched downstream modules without the integration build checking them. The publication hook checks changed files, which does not close that gap. On a cold cache, its `checkdecls` invocation also dynamically imports `MIPStarRE` (`scripts/Checkdecls.lean:49`), whose artifact these targets never produce. Build the complete library and axiom audit in the single locked invocation, and cover publication without preexisting project artifacts.

**F2:** A push can update remote main before returning a transport error. If the subsequent `ls-remote` fails, `published` remains false; if another update has advanced main beyond the train, equality also returns false. Both paths print “train refused” and call `record(..., False)`. In-memory fault injection reproduced both outcomes. Preserve an explicit unknown publication state when reconciliation fails, and recognize a remote descendant containing the train as published. The operator must not receive a definitive refusal after a potentially successful publication.

**F3:** `run_ci` inherits `MIPSTARRE_LAKE_ROOT` and calls the real bootstrap, whose first step invokes `lake-root.sh`. That helper explicitly rejects `/` in branch names (`local/bin/lake-root.sh:33`), so every generated `train/<timestamp>` branch fails under the documented external build-directory configuration. Executing the existing validator reproduced this rejection. Use a compatible branch name and cover the real bootstrap contract; the new tests currently remove this environment variable and replace bootstrap with a stub.
