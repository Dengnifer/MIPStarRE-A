## Review

**F1.** `run_gate` snapshots the base, statuses, and reviews, then the head-only REST guard runs under a `pr-<number>` lock. Two PRs can pass against base A before one creates base B, and CI or review can invalidate evidence after it was read. Serialize by base/repository through the merge mutation and verify the expected first parent as well as the head.

**F2.** The protocol at `local/protocols/review.md:381-395` requires four rounds and a disposition for every remaining finding. The implementation accepts any comment beginning `ADJUDICATION` and containing the head token, without validating rounds, dispositions, issue references, or operator identity.

**F3.** `gh_common.post_review` returns `exists` without replacing the old body, no pending review status is posted before a rerun, and final status publication failures only warn. This contradicts `local/protocols/review.md:277-282` and can preserve old clean evidence after a newly adverse rereview.

**F4.** `LOCAL_TIP`, merge base, and `FIX_ITERATIONS` are computed before acquiring the fix lock. A previous holder can leave an unpushed fix commit while the waiter queues; the remote head remains unchanged, so the waiter proceeds with stale evidence and can create a cap-plus-one commit.

**F5.** CI deliberately posts `local-ci/summary=pending` before refreshing step statuses. Autofix ignores that roll-up and can act on the preceding run’s failed step while CI is reading the same worktree. Dispatch requires a terminal exact-head failure summary.

**F6.** A marker is untrusted body text, not proof of attachment. Require `row.commit_id == HEAD_SHA` and the expected publisher before using a review to authorize a write-enabled fixer.

**F7.** An issue without a branch falls back to `main` while the generated contract permits commits. PR dispatch also never verifies the head repository or that the local branch tip equals GitHub’s `HEAD_SHA`. Writable sessions must be bound to a feature branch and exact commit.

**F8-F9.** Successful fixes push and rerun only CI; normal review skips bot commits, while the next autofix invocation exits before cap handling when nothing remains broken. The terminal review therefore never runs. The cap ritual also omits the required label removal from `local/protocols/autofix.md:160-170`.

**F10.** Every parsed finding is re-emitted as unchecked, including advisory findings, and both review summary and merge gate count all unchecked entries. This violates the trusted review rule that advisory-only feedback may be approved.

**F11-F13.** The previous CLI defaulted to `Addresses` unless closure was explicitly requested. The replacement always appends `Closes`, even over an existing `Addresses #N`, does not confirm that N is a real non-PR issue, adopts PRs by head without checking the requested base, and permits footer-only bodies.

**F14.** `issue_new.py` and `pr_open.py` destructively truncate and fence-break the authoritative GitHub body. At prompt ingress, `agent.sh` limits lines rather than the required 5,000 characters, so a single-line body can still inject tens of kilobytes. Preserve outbound Markdown and sanitize with a character bound only when framing model input.

**F15.** Existing QPBT paper-gap notes cite `\localissue{0002}`, but the macro renders the deleted `issues/` path; `local/personas/main.md:75-78` also prescribes it for new notes. Point historical references to the archive and use GitHub-native traceability for new issues.

**F16.** Active contributor instructions call `gh` directly against `LionSR/MIPStarRE` and describe the frozen Actions workflows as automatic. `local/DESIGN.md:54` likewise advertises classify/scout/track ports that this PR deletes. The operational documentation must match the GitHub-only local-execution model.

**F17.** The hook totals only the currently staged change, so serial sub-400-line commits bypass a policy defined over an entire workflow episode. This PR contains 10,253 workflow-layer changed lines. Enforce cumulatively against the episode’s merge base or describe the hook honestly as a per-commit heuristic.

No Lean, blueprint, or source-labelled declaration changed, so paper-statement fidelity is not implicated. `git diff --check`, changed-shell syntax checks, and AST parsing of seven changed Python files passed. The nine-test workflow suite could not be rerun in this read-only sandbox: eight tests failed during temporary-repository setup because no writable temporary directory was available; the hygiene test passed.
