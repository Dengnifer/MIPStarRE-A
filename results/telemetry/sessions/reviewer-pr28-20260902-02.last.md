## Review
Changes are required. This is a workflow-only PR: no Lean declaration, blueprint link, paper-gap note, `sorry`, or axiom changed, so mathematical source-statement fidelity is not implicated.
F1: `dispatch.sh` truncates each attachment to 100000 bytes, but then places the complete composed prompt in one argument at `dispatch.sh:601`. The 262144-byte aggregate check does not protect Linux's approximately 131072-byte per-argument limit; I reproduced success at 131071 bytes and `E2BIG` at 131072. A large diff plus the prior ledger and prompt overhead reaches that limit. Fix by using stdin or a prompt-file interface, or enforce a per-argument cap and update the session documentation.
F2: `ghc` is documented as fail-closed, but `review.sh:502` turns any `pr-reviews` failure into `[]`. A transient GitHub/API failure therefore resets `ROUND` to 1, discards prior findings, and can allow a fresh review to be published without the required history. This conflicts with `local/protocols/review.md:359-362` and `local/protocols/issues-prs.md:5-9`. Remove the fallback and fail before dispatching lanes.
F3: For a PR with no `.lean` file, `review.sh:941-946` selects `local/personas/orchestrator.md`; `build_task` then replaces the trusted `.github` review task with one sentence at `:583-586`. This PR follows that path. The reviewer loses the proof, safety, documentation, feedback, and verdict checklist, while the orchestrator persona has a different role and output contract. `local/protocols/review.md:9-11` says those criteria are unchanged. Keep the full trusted task and add a narrowly scoped workflow-review instruction or dedicated reviewer persona.
F4: After four prior marker reviews, `:503` computes round 5 but the normal lanes still launch at `:974`. The round-5 text is inserted before `## Findings` by `write_review:821`, while `combine_review:882` retains only the body after `## Review`, so the operator handoff is absent from the published review. Enforce the §12 handoff (with an explicit terminal forced-review path if needed) and build the banner inside the combined body before the unresolved-count check.
F5: `timeout --signal=TERM` at `:292` has no `--kill-after`, no positive-value validation, and no command preflight; GNU `timeout` is also unavailable on documented non-GNU environments. If TERM reaches `dispatch.sh`, its trap exits before the copy and telemetry finalizer at `dispatch.sh:638-660`; if TERM is ignored, the lane is unbounded. The cache-only capture then never becomes the permanent session record, and no marker review exists for adjudication. Use a portable, validated process-group timeout and record an explicit failed/incomplete session.
F6: `git sparse-checkout set` at `:541` changes the linked worktree's index/config before the `--dry-run` exit at `:960`, and the worktree is shared by CI and review. Skip-worktree entries can make `git status` at `:545` miss dirty tracked files and can race with CI. Use a disposable reviewer worktree or snapshot and restore sparse state; do not mutate the reusable worktree.
F7: The new “out of scope -> issue” rule at `local/protocols/review.md:366-368` does not require an issue number or stable disposition, yet `review.sh:606-607` explicitly permits findings against cross-file contracts and §12 requires every deferred finding to remain tracked (`local/protocols/review.md:391-402`). Narrow the exclusion to unrelated enhancement proposals and require a concrete tracked issue for anything deferred.
F8: `local/protocols/meta.md:15-20,35-47` requires an `EVOLUTION.md` entry for every protocol edit, but this PR adds none; `results/telemetry/events.md:206-208` specifically calls for the §12 amendment. In addition, the new #26 escalation text conflicts with the existing `EVOLUTION.md:359-363` rule naming a `needs-owner` issue. Add the dated Trigger/Change/Expected-effect entry and reconcile the owner and progress-log procedures.
F9: `REVIEW_MODEL="${MIPSTARRE_REVIEW_MODEL:-gpt-5}"` is always nonempty, and `run_agent:291` consequently overwrites `MIPSTARRE_CODEX_MODEL` with `gpt-5`. This breaks the documented cascade in `local/protocols/review.md:370-373`; the header and `local/DESIGN.md:137-145` are also stale. Preserve the cascade or update all policy and operator documentation to describe the intentional pin.
F10: The dispatcher branch receives both `--effort` and `prior-ledger.md` at `:271-279`, but the direct fallback at `:324-328` receives neither. The documented fallback therefore repeats resolved findings and runs at an uncontrolled reasoning effort. Mirror the controls in the fallback or remove/fail-closed that degraded path.
