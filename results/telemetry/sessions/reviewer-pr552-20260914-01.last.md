## Review
**F1:** `local/capacity-policy.json:26-40` defines `failure_patterns` as an ordered list, as required by `local/protocols/capacity.md:175-179`. The loader accepts only a dictionary, and `classify_failure` then hard-codes a different class order. With the shipped policy, `500 Internal Server Error` and `401 Unauthorized` both reproduce as `unknown`, disabling the intended health and death responses. The loader and tests must consume the shipped ordered schema.

**F2:** `local/protocols/capacity.md:119-121` assigns cap-file ownership to the controller when installed. `cmd_apply` nevertheless writes them before calling `init`, while `capacity_controller.py:845-875` performs `init` without `controller.lock`. A live tick can interleave these writes and leave caps, health files, and `state.json` from different control steps. Direct writes should be fallback-only, and `init` must take the controller lock.

**F3:** `cmd_resume` clears `paused`, `paused_at`, and `saved_caps` before calling the controller. If the controller or a later cap postcondition fails, the command raises after permanently recording an unpaused mode with no saved recovery value. Commit this state only after successful restoration, or roll it back on every failure.

**F4:** `full-speed-mode.md:323-324` requires controller failure during resume to leave admission paused. This script instead treats failure like absence, writes recorded caps directly, clears drain/stop files, and restarts all daemons. Only an actually absent legacy controller may use the fallback; a failed installed controller must terminate before any resume action.

**F5:** `_validate_accounts` permits primary disabled and second enabled, but `account_mode` returns `primary` whenever only one account is enabled. `owner-bin-codex:56-60` then rejects the second account's non-default `CODEX_HOME`. Derive a mode permitting second whenever second is enabled, or reject second-only briefs explicitly.

**F6:** The documented dispatch label contract is `[a-z0-9.-]{1,40}`, but validation merely removes control characters and truncates at 60. For example, `Primary Relay Key` is accepted by `run_mode.py` and makes every later dispatch fail at label preflight. Apply the same validation at briefing time.

**F7:** `account_router.py` uses status 6 for drain and status 4 for both capacity exhaustion and permanent configuration/model errors. `dispatch.sh` maps every nonzero status to retryable `refused`. Drain therefore retains claims through backoff instead of releasing, while malformed caps and model conflicts are misreported and retried. These outcomes need distinct statuses and explicit dispatch handling.

**F8:** The cutoff is checked before `reserve`, which may block for 1,800 seconds. There is no second check after reservation and before `codex` starts. Bound the reservation wait by remaining cutoff time and recheck immediately after success, releasing the account marker when expired.

**F9:** Telemetry can classify `endpoint_5xx` after completed model output, but `retry_is_safe` returns true for every transient class except `retries_exhausted`. This can rerun the full prompt over partial edits. Every model-started failure must require zero turns/output/usage and a completely clean worktree, including untracked files.

**F10:** `lane.sh` uses `set -u`, so nonzero CI and review exits are only printed. Its PR-head polling also has no failure assertion, after which `.done` is written unconditionally. `merge-daemon.sh:406-409` treats that file as successful refresh evidence. The lane must emit `needs-attention` unless head verification, CI, and review all succeed on the exact head.

**F11:** Filtering `??` permits a newly created Lean module or other partial worker output to be treated as clean. It can even satisfy a local import/build and then disappear from the pushed commit. Use the full porcelain result in both the lane and merge-daemon checks.

**F12:** `dispatch.sh:966-968` and `sessions.md:364-375` promise that retained requests are replayable by the janitor, but its pass list contains only spool expiry. No other consumer exists. Implement a bounded, admission-aware replay path or remove the replay guarantee and provide a real owner for these requests.

**F13:** The dispatcher writes integer `deadline_epoch` at `dispatch.sh:982-991`; the janitor parses an ISO `deadline` field instead. An entry with its own expired deadline survives indefinitely when the run has no cutoff. Dropping an entry also removes only the JSON file, leaving its private `.prompt.txt`; both files must be handled as one record.

**F14:** `signature(rows, occ)` excludes both `models` and `dead`, although those values are rendered as alarms. A newly off-policy model or unrepaired dead session can therefore be suppressed until the six-hour forced post, contradicting `full-speed-mode.md:211-224`. Include stable alarm state/counts in the digest.

**F15:** `pr_open.py`, `lane.sh`, and `daemon-scan.py` accept `claude/issue-*`, but `ready_report.issue_of` does not. Such PRs lose their issue number and associated parked-lane evidence and can be reported as unexplained. Reuse the canonical branch parser.

**F16:** `local/protocols/issues-prs.md:44-50` requires every GitHub operation to pass through `gh_common.py`. The new lane uses raw `gh` for issue data, head polling, and status reads, with failures sometimes swallowed. The new janitor and added merge-daemon calls have the same issue. Replace these calls with the shared layer.

**F17:** Per-session files under `results/telemetry/sessions/` are snapshots copied by `dispatch.sh`, not shared append logs. Two hosts can allocate the same role/scope/date/sequence from the same base; union merge would concatenate two unrelated event streams under one session identity. Exclude these paths and enumerate only genuinely append-only shared JSONL records.

**F18:** `capacity.md:103` and the implementation put ticks in runtime `watchdog/capacity/ticks.jsonl`, but line 136 still says every tick reaches committed `stages.jsonl`. Since protocols are normative, that stale assertion must be corrected.

The Lean change only adds umbrella imports. No public declaration changed, and the imported modules contain no `sorry`, axioms, or proof-integrity bypasses, so no source-statement drift was found. The authoritative patch matched the checkout diff; `git diff --check` and changed-shell `bash -n` checks passed. Exact-head local CI is reported green; write-requiring tests were not rerun in this read-only review.
