## Review

F1: Two publishers can both pass the store-existence check and move their private trees to separate incoming paths. One final rename wins; the other fails after its private tree has disappeared. Line 525 suppresses that failure, while cleanup does not track package staging. Failed final symlink creation is likewise hidden by Bash’s disabled `errexit` in the `|| true` context.

F2: A successful `cache get` does not imply complete cache coverage. Pinned Mathlib’s `Cache/Requests.lean:785-859` explicitly treats ordinary missing cache files as successful completion. This code immediately removes all write permissions, so a later build cannot compile those missing artifacts from source.

F3: A textually matching symlink returns before checking that its target exists. Lines 485-487 also retain any populated private tree without proving it matches the current manifest, and line 490 can fail yet still reach the explicit successful return. Status mode only tests apparent population, so it does not catch these states.

F4-F5: Both hot-main and CI preserve `.lake/` across manifest changes but validate only `-L`. Neither derives the current package-store key, verifies the target, or checks completeness/read-onlyness. The hot warmer also captures the tier-1 key before package preparation and can publish a snapshot even after package validation/build failure.

F6: Setup expands through `.lake/packages` before the warmer can replace a stale link. Its `git reset --hard` and ProofWidgets `mkdir -p` therefore target the symlink destination. This violates the new no-write shared-store contract and can affect an unrelated checkout.

F7: `sha256sum` bypasses the existing portable `sha256_stdin`; when absent, the nested pipeline failure is hidden by `printf` and the key collapses to `$CACHE_ROOT/packages/`. `mv -T` is also unavailable on the APFS/BSD environment explicitly supported elsewhere in this script.

F8: The primary checkout is documented as migrated to the shared link, but housekeeping still invokes `lake exe cache get` unconditionally. Its enclosing pipeline ends in `|| true`, so integrity and build failures can produce an apparently completed linter sweep.

F9-F10: `meta.md` requires a dated `events.md` observation and a cited trigger for protocol changes; this patch changes only `EVOLUTION.md`. The revised protocol also conflicts with the unchanged consumer procedure, the script header, `AGENTS.md` quick start, and the private-tree exception in the implementation.

Prior-ledger disposition: wrong-target relinking and directory nesting were narrowly fixed, but F1-F10 retain the underlying publication, validation, portability, migration, immutability, caller, signal/cleanup, housekeeping, and evidence problems. The abandoned package-mutex and `os.rename`/`EXDEV` findings no longer describe this head; the removed `test_package_store.py` and AGENTS trusted-script edit are absent. Continuing a build after an ordinary cache-fetch failure is protocol-intended and is not independently listed.

`bash -n` and `git diff --check` pass. The exact-head CI result is green, but its test discovery contains no package-store test; `shellcheck` was unavailable.
