F1: The direct fallback invokes `codex exec` without `</dev/null`, despite `dispatch.sh` explicitly documenting that inherited stdin is interpreted as additional prompt material. Piped input can therefore bypass the `UNTRUSTED_DATA` envelope and affect the machine-parsed verdict. The fallback also lacks `--kill-after`, effort propagation, and prior-ledger context. It must either fail closed when dispatch is unavailable or reproduce dispatch’s stdin, timeout, context, and effort controls.
F2: The remaining allowance is calculated from cumulative original file sizes, but truncation is reported only when the current file alone exceeds `MAX_CONTEXT_BYTES`. With an 80 KB diff followed by a 30 KB ledger under the 100 KB aggregate limit, only 20 KB of the ledger is included and no truncation marker is emitted; after a 100 KB first attachment, later attachments disappear silently. Track emitted bytes and report every aggregate truncation. Reconcile this behavior with `local/protocols/sessions.md:243`, which still documents per-context and 256 KiB limits.
F3: Any review body containing `mipstarre-review pr=` and even a one-character hexadecimal `head=` value increments `ROUND`; the PR number, full SHA, review commit, and expected author are not validated. Moreover, round five still dispatches full review agents. The cap text added before `## Findings` is discarded when the combined review extracts content after `## Review`. Authenticate prior records and hand off to the §12 adjudication path before dispatching another full round, while preserving that handoff in published evidence.
F4: `git sparse-checkout set` mutates repository configuration, index flags, and checkout contents before both the dirty-tree check and dry-run exit. Because `resolve_worktree` returns the branch worktree subsequently used by CI and autofix, reviewer-only exclusions persist into later lifecycle stages. Use an isolated reviewer worktree or restore the exact prior sparse-checkout state through a trap; dry runs must remain non-mutating.
F5: `local/protocols/review.md:369` documents the cascade `MIPSTARRE_REVIEW_MODEL` → `MIPSTARRE_CODEX_MODEL` → dispatcher default, but the unconditional `gpt-5.6-sol` default makes the first value always nonempty and overrides `MIPSTARRE_CODEX_MODEL`. `local/DESIGN.md:139` also specifies ultra effort while this implementation defaults to high. Either implement the existing normative contract or amend all corresponding documentation and tests to record the intentional new policy.
F6: Normal summarization correctly uses the published capture, but the failure-recovery command still references `$CAPTURE` under the runtime cache. Replaying it can place an ephemeral absolute path in `sessions.jsonl`, and telemetry deduplication can prevent a later correction. Recovery must summarize the published path; failure to publish the final capture should fail closed or be repaired before registry insertion.
