## Review

**F1:** Queue tickets store resolved paths, but `dispatch.sh` uses logical `pwd` for both its worktree lock and `MIPSTARRE_DISPATCH_WORKTREE`. A symlink alias therefore differs from the ticket’s path and obtains a different lock. An in-memory router test admitted an unrelated dispatch through `/proc/self/cwd` while its resolved worktree was reserved. This permits concurrent writers; queued launches through aliases also fail their own ticket check. Canonicalize the dispatcher path before deriving either identifier and test both cases.

**F2:** Non-JSON lines become `{}`, which qualifies them for refusal matching. Reproductions using the normal summary lines `wall_s: 503` and `tokens_total: 150295` each counted one refusal. Session names and worktree paths can trigger it too. `refresh()` then latches `HOLD`, stopping healthy admissions until operator intervention. Restrict detection to error events or recognized diagnostic lines and add clean-log regression coverage.

**F3:** `child_environment()` drops `MIPSTARRE_LAKE_ROOT` through both launch stages. `build-cache.md` §2 requires preserving this export through dispatch, where it enables validation and the restricted `--add-dir` grant. Queued workers using prepared external `.lake` directories consequently lose required build-write access. Preserve this configuration through the existing validation path.
