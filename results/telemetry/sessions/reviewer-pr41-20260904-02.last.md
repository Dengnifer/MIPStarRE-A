## Review

F1: Codex’s documented `workspace-write` policy protects `<writable_root>/.git` and resolved worktree Git directories as read-only, even when the repository is explicitly listed in `writable_roots`. With `approval_policy="never"`, failures cannot escalate. This blocks duties required by `local/personas/main.md`, including `git worktree add`, commits, pushes, fetches, merges, ref updates, and branch cleanup. The launcher needs an execution policy that actually permits Git metadata writes. See the [official Codex sandbox documentation](https://learn.chatgpt.com/docs/agent-approvals-security).

F2: `dispatch.sh`, `ci.sh`, and the shared workflow utilities resolve the runtime root as `${MIPSTARRE_CACHE_ROOT:-$HOME/.cache/mipstarre-dev}`. The launcher instead always grants `/home/drx/.cache/mipstarre-dev`. When the supported override is set, child tools write outside the granted roots and fail immediately under `approval_policy="never"`. Derive the allowlisted path from the same environment contract.

`bash -n local/bin/main-session.sh` and `git diff --check` pass, and Codex CLI 0.152.1 accepts the fresh/resume option ordering.
