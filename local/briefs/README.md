# Briefs

One design brief per issue, committed. A brief is what turns a line in the
chapter plan into a contract a worker can implement and a reviewer can check
against.

**Empty so far.** Naming: `<issue>-<slug>-brief.md`.

Write one from [`../templates/skeleton-brief.md`](../templates/skeleton-brief.md).
The lifecycle is in [`../protocols/bootstrap.md`](../protocols/bootstrap.md)
stage 4.2 and in [`../README.md`](../README.md): the brief is written, reviewed
independently, adjudicated by the main session, and only then turned into the
issue body. Implementation starts from the adjudicated brief, never from a
draft.

A brief that leaves the statement to the implementer produces a pull request
nobody can review against anything. If you cannot fix the statement, that is
the finding — report it instead of writing a vague brief.
